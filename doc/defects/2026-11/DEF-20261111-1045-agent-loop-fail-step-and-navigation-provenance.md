# [DEF-20261111-1045] Agent Loop Lacks First-Class Failure Mechanism and Navigation Provenance Guard

- **Status:** `Resolved`
- **Opened:** 2026-11-11 10:45
- **Closed:** 2026-11-13 12:54
- **Component:** `neodymium-core`
- **Scope:** `Framework & AI/Prompt`
- **Symptom:** When an automated test encounters a CAPTCHA, bot challenge, unexpected error page (404/500), or missing element on an action instruction (e.g. "Click on first available product"), the AI agent thrashes across turns and attempts rogue workarounds—including calling the `navigate` tool to visit uncommanded external websites (e.g. `https://www.ifolor.ch`) or same-site URLs inferred from project tool definitions or session data—instead of acting as a deterministic QA executor and failing cleanly.
- **Root Cause:**
  1. `AgentToolLoopStep` only registers `complete_step` and browser/assertion tools; there is no native `fail_step` tool. On malformed responses, the fallback prompt explicitly instructs the agent: *"If the step's goal is complete, invoke 'complete_step'. Otherwise, invoke the next browser tool"*, trapping the model in a succeed-or-mutate loop.
  2. `QualityJudgeToolInterceptor` only inspects CSS/XPath element selector quality, exempts `navigate` from checks, and exits early when `neodymium.ai.judge.enabled=false`. There is no pre-execution provenance guard policing autonomous `navigate` calls against uncommanded hosts or paths.
- **Detection Gap ("What did we miss?"):** Existing agent loop and interceptor unit tests verified successful step completion (`complete_step`) and CSS/XPath locator deliberation, but did not test agent loop exit paths when targets are blocked/unreachable or when the LLM proposes uncommanded `navigate` calls mid-test.
- **Resolution:**
  1. Register a first-class `fail_step(reason)` tool in `AgentToolLoopStep` that auto-escalates once to `ContextLevel.RICH` if invoked below `RICH` with zero prior tool executions (attaching `[DOM empty or omitted]` even on blank error screens), omits `fail_step` on pure `(visual)` verification steps so Stage 2 `VerifyOperationStep` always executes, and otherwise sanitizes `reason`, guarantees a `VISUAL` failure screenshot, and throws `ConclusiveFailureException` (preserving `(bug)`, `(optional)`, `TryCatchStep`, token-budget completion grace, clean companion recordings, and single Aura HUD failure pauses).
  2. Introduce `CompositeToolInterceptor` and `NavigationProvenanceInterceptor` in `org.neodymium.ai.tool.guard` (wired ahead of `QualityJudgeToolInterceptor`) enforcing blank-page, TLD-preserving host/registrable-domain (with host-attached path/`/?query` enforcement), and token-bounded relative path/query/anchor provenance rules (with idempotent `%XX` + IDN canonicalization, `${baseUrl}/path` double-slash normalization, parent/query truncation guards, and non-misleading two-branch `RETRY_WITH_FEEDBACK` recovery guidance) before `Selenide.open` executes, configurable via `neodymium.ai.navigation.guard.enabled` and `neodymium.ai.navigation.allowedHosts`.
  3. Harden `AgentToolLoopStep` operating rules and malformed-response fallback prompt with a concise deterministic QA executor persona and target-presence rule for 404/error/CAPTCHA pages.
