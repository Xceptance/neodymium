# [DEF-20261125-1125] Pure Visual Step Hashes Full-Page Screenshot With fullPage=false Causing SSIM Mismatch on Strict Replay

- **Status:** `Resolved`
- **Opened:** 2026-11-25 11:12
- **Closed:** 2026-11-25 12:06
- **Component:** `neodymium-core` (`VerifyOutcomeStep.java`, `VisualBaselineGateStep.java`, `SelenideTargetExecutor.java`, `PageAnalyzer.java`, `SutState.java`, `BrowserSutState.java`, `MockSutState.java`, `ExecuteActionsStep.java`, `ScreenshotWriter.java`)
- **Scope:** `Framework`
- **Symptom:** In Jenkins build #304 on `org.neodymium.ai.integration.verla.search.basic.SearchGermanTest#replay()[1]`, Step 4 (`Die gezeigte Landesflagge ist die Flagge von "${country}" (visual).`, `isFullPageReq = false`, no mutating actions) failed under `REPLAY_STRICT` with `DivergenceException: Visual SSIM score below threshold (score: 0.4663 < 0.99)`. During `live()`, Turn 2 had executed `query_dom` and captured a `1500x2125` full-page screenshot into `ExecutionContext.KEY_LAST_STATE`, while `ExecuteActionsStep` captured a `1500x857` viewport screenshot into `ExecutionContext.KEY_POST_ACTION_STATE` at step end. `VerifyOutcomeStep` hashed the `1500x2125` full-page image while recording `step.setFullPage(false)`, and `VisualBaselineGateStep` then compared a `1500x857` viewport replay screenshot against the full-page SSIM matrix. Reproducing this scenario in real headless Chrome further revealed a secondary `0.9036 < 0.99` SSIM failure at `1500x857`: once Turn 2's full-page CDP capture ran with `captureBeyondViewport: true`, Chromium suppressed the 15 px vertical scrollbar without restoring root layout afterward, causing `live()` to record a scrollbar-less viewport baseline (`clientWidth=1500`) while `REPLAY_STRICT` rendered with the scrollbar (`clientWidth=1485`).
- **Root Cause:**
  1. **Obsolete `KEY_POST_ACTION_STATE` discard in `VerifyOutcomeStep`:** Lines 180–198 of `VerifyOutcomeStep.java` retained a pre-refactor heuristic that discarded `KEY_POST_ACTION_STATE` whenever `step.getActions().isEmpty() && !isFullPageReq`, falling back unconditionally to `KEY_LAST_STATE`. Even though `ExecuteActionsStep` already captures a fresh post-step screenshot matching `isFullPageReq` into `KEY_POST_ACTION_STATE` for visual steps, pure `(visual)` steps threw away that viewport capture and hashed `KEY_LAST_STATE` (which multi-turn `AgentToolLoopStep` loops overwrite with a full-page capture whenever `activeContextLevel` is `VISUAL_LEAN` / `VISUAL_RICH`).
  2. **Missing capture-scope provenance on `SutState`:** `SutState` and `BrowserSutState` did not record whether attached screenshots were captured full-page (`true`) or viewport-only (`false`), preventing `VerifyOutcomeStep` and `VisualBaselineGateStep` from detecting full-page vs. viewport mismatches on `KEY_POST_ACTION_STATE` and `KEY_LAST_STATE`.
  3. **Escalated `ContextLevel` overriding explicit `isFullPage=false`:** When `VerifyOutcomeStep` fell back to a fresh capture, it passed escalated `activeLevel` (`VISUAL_LEAN` / `VISUAL_RICH`) to `executor.captureState(level, false)`. `PageAnalyzer.captureScreenshotInternal` then computed `forceFullPage = isFullPage || (level != null && level.isFullPageScreenshot())`, silently capturing a full-page screenshot despite `isFullPage = false`.
  4. **CDP `captureBeyondViewport: true` leaving root scrollbars hidden in `ScreenshotWriter`:** `ScreenshotWriter#takeScreenshotWithCDP` and `#takeScreenshot` invoke CDP `Page.captureScreenshot` with `captureBeyondViewport: true`, which triggers Chromium's `hide_scrollbars` preference during full-page capture without triggering a subsequent root scrollbar relayout. Subsequent viewport captures on the same page load therefore omitted the 15 px vertical scrollbar and diverged (`SSIM 0.9036 < 0.99`) against fresh strict replay runs.
- **Detection Gap ("What did we miss?"):**
  1. `VerifyOutcomeStepTest.testVisualStepDoesNotConsumeStalePostActionState` used untagged `MockSutState` instances to assert only the pre-refactor inverse case (stale full-page `KEY_POST_ACTION_STATE` vs. viewport `KEY_LAST_STATE`), without testing a pure `(visual)` step having a fresh viewport `KEY_POST_ACTION_STATE` alongside a full-page `KEY_LAST_STATE` from an escalated multi-turn loop.
  2. `VerifyOutcomeStepTest.testViewportVisualStepEscalatingToVisualLeanEnforcesViewportFullPageFalse` only asserted `step.isFullPage() == false` on an untagged viewport mock already sitting in `KEY_LAST_STATE`, without covering a full-page `KEY_LAST_STATE` or verifying the fallback `captureState(ContextLevel.VISUAL, false)` call.
  3. Unit tests using mocked `SutState` did not exercise real Chromium CDP `captureBeyondViewport: true` layout side effects across consecutive full-page and viewport captures on the same page.
- **Resolution:**
  1. Added backward-compatible `default Boolean isFullPageScreenshot()` on `SutState` (with `Boolean` provenance stored in `BrowserSutState` and `MockSutState`) and populated it in `SelenideTargetExecutor#captureState`.
  2. Updated `PageAnalyzer#captureScreenshotInternal` so explicit `isFullPage` is honored directly instead of being overridden by `level.isFullPageScreenshot()` (preserving `level.isFullPageScreenshot()` in the 2-arg `captureScreenshot(title, level)` overload).
  3. Updated `VerifyOutcomeStep` to prefer `KEY_POST_ACTION_STATE` for all visual steps (including empty-action pure visual steps) whenever its capture scope matches `isFullPageReq`, discard/skip any `KEY_POST_ACTION_STATE` or `KEY_LAST_STATE` whose `isFullPageScreenshot()` contradicts `isFullPageReq`, fall back cleanly to `ContextLevel.VISUAL` / `ContextLevel.VISUAL_LEAN` matching `isFullPageReq`, guard Block 4 `preCapturedPostState` against full-page mismatch, and call `step.setFullPage(isFullPageReq)` unconditionally.
  4. Updated `VisualBaselineGateStep#executePostActionCheck` to recapture if `KEY_POST_ACTION_STATE.isFullPageScreenshot()` contradicts `isFullPageReq`, and updated `ExecuteActionsStep` to clear stale `KEY_POST_ACTION_STATE` before entering `HealingRequiredException` recovery.
  5. Updated `ScreenshotWriter#takeScreenshotWithCDP` and `#takeScreenshot` to measure `[verticalScrollbarWidth, horizontalScrollbarHeight]` before beyond-viewport CDP captures and, in `finally` before restoring scroll offset, restore root scrollbar layout via a guarded `overflow-x`/`overflow-y` relayout on `document.documentElement` whenever pre-existing scrollbars shrank.
- **Safety Net Added:**
  - Updated `VerifyOutcomeStepTest#testVisualStepDoesNotConsumeStalePostActionState` to tag mock states with explicit `Boolean.TRUE` / `Boolean.FALSE` capture-scope metadata.
  - Added `VerifyOutcomeStepTest#testPureViewportVisualStepUsesViewportPostActionStateOverFullPageLastState` (verifying pure `(visual)` step baseline recording + `VisualBaselineGateStep` strict replay).
  - Added `VerifyOutcomeStepTest#testPureViewportVisualStepWithoutPostActionStateRejectsFullPageLastStateAndCapturesFreshViewport`.
  - Added `VerifyOutcomeStepTest#testPureFullPageVisualStepWithoutPostActionStateRejectsViewportLastStateAndCapturesFreshFullPage`.
  - Added `VisualBaselineGateStepTest#testExecutePostActionCheckRecapturesWhenPostActionStateFullPageMismatches`.
  - Added `ScreenshotWriterScrollbarRestoreTest` covering CDP and DevTools beyond-viewport captures, exception paths, within-viewport skips, and no-initial-scrollbar skips.
  - Added real headless-Chrome mock-LLM E2E regression tests in `VisualBaselineFullPageScopeSandboxMockTest` (`testPureViewportVisualStepWithEscalatedQueryDomReplaysStrictly` and `testPureFullPageVisualStepReplaysStrictly`) on VÉRLA.
