# [DEF-20261109-0756] Interactive Console Server Uses Non-Standard Status "finished" Causing False UNKNOWN FAIL in Reports

- **Status:** `Resolved`
- **Opened:** 2026-11-09 07:56
- **Closed:** 2026-11-09 09:56
- **Component:** `neodymium-core`, `aura-manager`
- **Scope:** `Framework & Test/Harness`
- **Linked Ticket:** GitLab Issue #111 (`[neo] Interactive Console Simulation Uses Non-Standard Status Causing False UNKNOWN FAIL`)
- **Symptom:** Test executions originating from `InteractiveConsoleServer` simulations (such as `CheckoutFlowTest`) display a red `UNKNOWN FAIL` badge in the Aura Manager run report overview table, yet clicking on the test row opens the side panel where all test steps are displayed as passed (green).
- **Root Cause:** In `InteractiveConsoleServer.runSimulationInternal()`, completing a simulation successfully without errors set `activeState.addProperty("status", "finished")`, conflating the interactive session lifecycle phase with the test execution outcome. In contrast, standard Neodymium runners (e.g. `InteractiveConsoleListener`) set `"passed"`. Because `TestExecutionDto.getDisplayStatusKey()`, `AuraReportDataService`, `LocalRunJsonStorageService`, and `generate_run_json.py` only recognized `"passed"`, `"passed-clean"`, `"succeeded"`, or `"healed"` as successful outcomes, executions with raw status `"finished"` fell through to `FAILED_UNKNOWN` despite having 0 failed steps. Furthermore, failing executions with status `"finished"` fell through fallback logic into `effStatus = "ignored"` in variation repositories and `default -> pass++` in report generation. Additionally, when hardening report aggregation fallbacks to `unknownCount++`, missing `"running"` branches in `ingestExecution` and `RunStorageSyncService.syncRunFromDisk` captured in-flight executions as unknown failures.
- **Detection Gap ("What did we miss?"):** Unit tests for `AuraReportDataService` and `RunStorageSyncService` tested explicit statuses `"passed"`, `"failed"`, and `"running"`, but did not assert on test execution files containing the raw string `"finished"` paired with zero or non-zero failed steps, nor did they assert on aggregation counters when active runs contained in-flight executions.
- **Resolution:**
  1. Updated `InteractiveConsoleServer.java` to scan `allSteps` for failed/error/failure steps before setting `activeState` outcome (setting `"failed"` if any step failed, otherwise `"passed"`), guarding against non-primitive Gson elements.
  2. Centralized execution status computation into `AuraReportDataService.computeEffectiveStatus(...)` and failure extraction helpers, delegating from `TestExecutionDto.getDisplayStatusKey()`, `LocalRunJsonStorageService.java`, and `RunStorageSyncService.java`.
  3. Defensively recognize `"finished"` with `failedStepsCount <= 0` and no errors as `PASSED` / `"passed-clean"` (or `"succeeded-fixed"` if linked bugs exist), including in `addBugToExecution` and `removeBugFromExecution`, symmetrically handling `"NONE"` / blank / null failure strings.
  4. Preserved clean bug unlinking semantics by tying `isKnown` and `isFixed` directly to active bug presence, allowing unlinking to flip executions cleanly back to `failed-unknown` / `passed-clean`.
  5. Correctly handle active runs (`isRunActive`) across `LocalRunJsonStorageService.buildRunJsonContent`, `AuraReportDataService.ingestExecution`, `RunStorageSyncService.syncRunFromDisk`, and `TestExecutionDto.getDisplayStatusKey()`, preventing running tests from being classified as unknown failures or ignored.
  6. Ensured failing `"finished"` and interrupted executions (with `failedStepsCount > 0` or error/failure attributes) map to `failed-known` / `failed-unknown` across `AuraReportDataService.java`, `LocalRunJsonStorageService.java`, `RunStorageSyncService.java`, and `generate_run_json.py`, without swallowing into `ignored` or inflating pass counts.
  7. Hardened unmapped fallback handling in `AuraReportDataService.buildRunReportDto()` to `default -> unknown++` with case-insensitive lowercasing while explicitly skipping in-flight running executions during active runs.
  8. Handled `"NONE"` failure strings symmetrically in `generate_run_json.py` to prevent clean finished or running executions from falsely registering as errors during offline report generation.
- **Safety Net Added:** Added permanent regression tests in `AuraReportFinishedStatusMappingTest` asserting clean and failing `"finished"`, `TestExecutionDto` running/null states, in-flight `"running"` execution non-inflation during active run ingestion and sync, interrupted runs with and without failures, and bug unlinking. Updated `InteractiveConsoleServerTest.testInteractiveConsoleJsApplyStatePreservesFinalPauseToken` verifying pauseId preservation. Verified `RunStorageSyncServiceTest` (26 tests) and `AuraReportBugUnlinkTest` (10 tests) pass green.
