# [DEF-20261113-1735] Pending Confirmation Loss Across Clarifying Turns, Partial Consumption, and Failed LLM Turns

- **Status:** `Resolved`
- **Opened:** 2026-11-13 17:35
- **Closed:** 2026-11-13 17:35
- **Component:** `aura-manager`
- **Scope:** `Framework & AI/Prompt`
- **Symptom:** Issuing a destructive action requiring confirmation (`delete_test` or `cancel_run`), then sending a follow-up clarifying question (or encountering an upstream LLM error on a subsequent turn), silently wiped prior unexpired confirmations—causing either follow-up Confirm button clicks to fail or forcing the LLM to restart confirmation from scratch. Additionally, confirming only one of two queued actions in chat wiped the unconsumed sibling confirmation, and `ConfirmationBarrierToolCallback` relied on `endsWith("_test")` instead of explicit tool-to-parameter mapping.
- **Root Cause:** [`AuraChatService`](file:///home/robert/Development/internal/neodymium/neodymium/aura-manager/src/main/java/com/xceptance/aura/chat/service/AuraChatService.java) removed the entire prior confirmation map in `takeValidPriorConfirmations(sessionKey)` and blindly overwrote `pendingConfirmationsBySession` with only `issuedInCurrentTurn` when `!issuedInCurrentTurn.isEmpty()` (leaving prior unconsumed confirmations evicted permanently on plain-text turns, partial consumptions, and LLM errors). Furthermore, `removeByActionId` iterated and removed from session maps without `computeIfPresent` atomicity against concurrent merges, and target parameter resolution checked `"testPath"` vs `"runId"` via an imprecise `endsWith("_test")` heuristic.
- **Detection Gap ("What did we miss?"):** Existing `AuraChatServiceTest` scenarios verified immediate two-turn confirmation, failed initial confirmation, and UI Confirm/Cancel on a single turn, but did not test an intervening read-only clarifying turn, partial consumption across two queued destructive actions, or an upstream LLM exception occurring while an earlier confirmation was still pending.
- **Resolution:** Added atomic `mergePendingConfirmations(...)` backed by `ConcurrentHashMap.compute(...)` in [`AuraChatService`](file:///home/robert/Development/internal/neodymium/neodymium/aura-manager/src/main/java/com/xceptance/aura/chat/service/AuraChatService.java) to merge surviving unexpired prior confirmations with newly issued confirmations (or with `newlyIssued = null` on LLM failure so prior valid confirmations survive while failed-turn confirmations are discarded). Switched `getPendingConfirmations` and `removeByActionId` to `computeIfPresent`, and replaced the `endsWith("_test")` heuristic with `DESTRUCTIVE_TOOL_TARGET_PARAMS` + `resolveDestructiveTargetParam(...)`.
- **Safety Net Added:** [`AuraChatServiceTest`](file:///home/robert/Development/internal/neodymium/neodymium/aura-manager/src/test/java/com/xceptance/aura/chat/service/AuraChatServiceTest.java) methods `testClarifyingTextTurnAndLlmErrorPreservePriorPendingConfirmations` and `testPartialConsumptionInChatPreservesSiblingPendingConfirmation`.
