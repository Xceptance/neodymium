# [DEF-20261113-1431] Confirmation State Leak on Failed Turns, Pre-Barrier Trace Exposure, and Non-Thread-Safe Trace Collections

- **Status:** `Resolved`
- **Opened:** 2026-11-13 14:31
- **Closed:** 2026-11-13 14:31
- **Component:** `aura-manager`
- **Scope:** `AI/Prompt & Framework`
- **Symptom:** If an LLM turn threw an upstream exception after executing a destructive tool's dry-run, its pending confirmation token still persisted across to the next turn. Additionally, the Thinking trace logged raw pre-barrier output with injected confirmation tokens unredacted and appended entries to unsynchronized `ArrayList`/`LinkedHashSet` instances during parallel tool calls; UI also lacked direct Confirm/Cancel action controls, and `error` messages were replayed to the LLM on future turns.
- **Root Cause:** `AuraChatService.runChatWorkflow` persisted `issuedInCurrentTurn` inside a `finally` block regardless of turn failure, wrapped `TraceObservingToolCallback` inside `ConfirmationBarrierToolCallback` (recording pre-barrier arguments/responses containing `confirmationToken`), and mutated unsynchronized `ArrayList`/`LinkedHashSet` instances without thread guards. `ChatMessageDto` also lacked an `error` flag so failed turns polluted `buildHistoryMessages`, and confirmation tokens were not exposed as UI-safe server-referenced action buttons.
- **Detection Gap ("What did we miss?"):** Earlier unit tests only exercised sequential single-tool happy paths and never simulated an exception mid-turn, parallel tool callbacks, injected-token trace inspection, or failed-turn history replay.
- **Resolution:** Replaced the `finally` confirmation persistence in [`AuraChatService`](file:///home/robert/Development/internal/neodymium/neodymium/aura-manager/src/main/java/com/xceptance/aura/chat/service/AuraChatService.java) with post-completion persistence only, inverted decorator order (`TraceObservingToolCallback` wraps `ConfirmationBarrierToolCallback`), redacted `confirmationToken` values in trace logs with multiline 2-space pretty JSON, synchronized trace/action collections, added `PendingConfirmationDto` and `/api/chat/confirm` + `/api/chat/cancel` UI action endpoints in [`AuraTestChatController`](file:///home/robert/Development/internal/neodymium/neodymium/aura-manager/src/main/java/com/xceptance/aura/test/controller/AuraTestChatController.java), and marked error replies with `ChatMessageDto.error = true` so `buildHistoryMessages` skips them.
- **Safety Net Added:** [`AuraChatServiceTest`](file:///home/robert/Development/internal/neodymium/neodymium/aura-manager/src/test/java/com/xceptance/aura/chat/service/AuraChatServiceTest.java) methods `testFailedTurnDoesNotPersistPendingConfirmation`, `testThinkingTraceLogsPostBarrierPrettyJsonAndRedactsInjectedToken`, `testParallelToolCallsThreadSafeTraceAndActions`, `testExplicitUiConfirmAndCancelPendingAction`, and `testBuildHistoryMessagesSkipsErrorMessages`; [`AuraTestChatControllerTest`](file:///home/robert/Development/internal/neodymium/neodymium/aura-manager/src/test/java/com/xceptance/aura/chat/controller/AuraTestChatControllerTest.java) method `testConfirmAndCancelEndpointsExecuteOrClearPendingConfirmation`.
