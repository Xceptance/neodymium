# [DEF-20261124-1012] Online LLM Self-Healing Retains Failed Replay Status, Misrenders Healed Steps as PENDING, and Misattributes Downstream Steps & LLM Calls

- **Status:** `Resolved`
- **Opened:** 2026-11-24 10:12
- **Closed:** 2026-11-24 12:35
- **Component:** `neodymium-core` (`ExecuteActionsStep`, `AgentToolLoopStep`, `ExecutionContext`, `PreliminaryReportListener`, `TestExecutionReport`, `InteractiveStateBuilder`, `InteractiveConsoleEngine`), `aura-manager` (`TestExecutionDto`, `TestRunEntity`, `RunStorageSyncService`, `report-manager.js`)
- **Scope:** `Core Engine` & `UI / Report Rendering`
- **Issue:** [Xceptance/neodymium#576](https://github.com/Xceptance/neodymium/issues/576), [Xceptance/neodymium#575](https://github.com/Xceptance/neodymium/issues/575), GitLab `#152`
- **Symptom:**
  When `REPLAY_WITH_HEALING` failed offline heuristic healing (due to a changed selector and low DOM similarity) and escalated via `HealingRequiredException` to `AgentToolLoopStep` for online LLM self-healing:
  1. Even after `AgentToolLoopStep` successfully healed the selector and executed the action, the step remained in `FAILED` status with `failed = true` and retained the initial replay `failureReason` (`Element not found ...`) in both `PlaybookStep` and `TestExecutionReport`, leaving overall execution mode as `RECORDING` instead of `HEALED`.
  2. `PlaybookRecorder` overwrote the step with `healed: false` and failed status, losing the healed action metadata (`healed = true`, `expectedTarget`, `originalTarget`), while `PreliminaryReportListener` retained the aborted failed replay action alongside missing post-step visual capture.
  3. Subsequent zero-LLM replay steps whose block-local `stepIndex` matched an earlier healed step's `globalIndex` (offset by `before` hook steps) erroneously displayed duplicated `llmCalls` in `InteractiveStateBuilder`.
  4. In the Aura Manager Run Report (`report-manager.js`) and Runs List (`batch-history.html`), finished `HEALED` steps rendered a `PENDING` context-level badge, zeroed out `action`, `screenshot`, and `LLM call` counts, and displayed `-` / `N/A` timings; downstream passing/healed steps risked being overwritten to `NOT RUN` by `hasEncounteredFailure`; and a single online-healed test was double-counted as both `Healed` (`✨ 1`) and `AI-Driven` (`1` striped bar) in the Status Breakdown bar and area breakdown.
  5. Passing `HEALED` runs (`console-execution-*.json` / `TestExecutionReport`) retained top-level `error`, `errorMessage`, `failureReason`, and `failureStackTrace` from the recovered `HealingRequiredException`.
- **Root Cause:**
  1. `PlaybookToolReplayer` eagerly mutated `step.setStatus(PlaybookStepStatus.FAILED)`, `step.setFailed(true)`, and `step.setFailureReason(...)` before throwing the exception caught and re-wrapped into `HealingRequiredException` by `ExecuteActionsStep`. Neither `HealingRequiredException` handler reset those fields before pushing `AgentToolLoopStep`, so `ExecuteActionsStep`'s `endHookStep` skipped the `if (!step.isFailed() && ...)` completion block that assigns `PlaybookStepStatus.HEALED`.
  2. `ExecuteActionsStep`'s `HealingRequiredException` handlers did not push `postStepVisualCaptureStep` after `AgentToolLoopStep`, preventing post-healing `StateCapturedEvent` screenshot capture.
  3. `AgentToolLoopStep` dispatched 2-arg `ActionExecutedEvent(canonicalAction, true)` instead of preserving pre-healing targets (`ExecutionContext.KEY_PRE_HEALING_TARGETS`), resolving runtime variables into `resolvedAction`, and propagating `isHealedStep`. Its 0-arg constructor passed a non-null default registry, masking `KEY_TOOL_REGISTRY` overrides.
  4. `PreliminaryReportListener` did not include `"HEALED"` in `isStepSuccess`, did not clear stale `failureReason` upon successful completion, lacked `ReportStepEntry.removeActionIf(...)` to prune aborted failed replay actions, and checked only top-level `"HEALED"` status string rather than `ReportStepEntry.isHealed()` in `recalculateMetrics()`. `InteractiveConsoleEngine.reconcileTestOutcome(false, ...)` also omitted `"healed"` from `wasPassed`.
  5. `InteractiveStateBuilder` matched `report.getLlmCalls()` even when `reportStep != null` and matched `call.getStepIndex() == stepIndex || call.getStepIndex() == globalIndex`, conflating block-local index with global flat index; `reportStep` lookup checked `entry.getStepIndex() == stepIndex || entry.getStepIndex() == globalIndex` in list order and allowed `entryRaw == null` to bypass instruction matching.
  6. In `aura-manager`: in `report-manager.js`, `isUnexecutedOrSkipped` omitted `!isHealed`, composite sub-step aggregation mapped `'HEALED'` to `'passed'`, and `hasEncounteredFailure` lacked a recorded-execution guard; `TestExecutionDto.isAiDriven()` and `report-manager.js` line 3453 counted healed replay tests with LLM calls as `AI-Driven`; `RunStorageSyncService` set `isAi` without `!isHealed` and incremented both `calc*Healed` and `calc*Ai` via independent `if` statements; and `TestRunEntity.get*AiCountSafe()` did not clamp legacy double-counted AI counts against `categoryTotal - healedCount`.
  7. `StateMachineRunner` writes caught `HealingRequiredException` to `ExecutionContext.KEY_LAST_EXECUTION_ERROR`; `ExecuteActionsStep.endHookStep` never cleared recovered `HealingRequiredException` entries on step success, and `PreliminaryReportListener.populateContextMetadata()` repopulated `failureReason` and `failureStackTrace` from `KEY_LAST_EXECUTION_ERROR` without checking `!this.report.isSuccess()`.
- **Detection Gap ("What did we miss?"):**
  Existing replay unit tests in `ExecuteActionsStepTest` verified routing to `AgentToolLoopStep` on `HealingRequiredException` or replaying pre-healed steps, but never executed a full `REPLAY_WITH_HEALING` -> `PlaybookToolReplayer` failure -> `AgentToolLoopStep` mock LLM recovery -> `PreliminaryReportListener` (`SessionFinishedEvent`) end-to-end flow, nor asserted `KEY_LAST_EXECUTION_ERROR` cleanup or top-level `failureReason`/`failureStackTrace == null`. `InteractiveConsoleEngineTest` only tested `before` vs `steps` block separation at index `0` and missed `"healed"` failure reconciliation. `PreliminaryReportListenerTest` did not test `SessionFinishedEvent(success=true)` with a stale `HealingRequiredException` in `KEY_LAST_EXECUTION_ERROR`. Neither `TestExecutionDtoTest`, `TestRunEntityTest`, nor `StaticResourceSyntaxTest` covered online-healed `REPLAY_WITH_HEALING` mutual-exclusion with `AI-Driven` or `report-manager.js` healed-step metrics/downstream guards.
- **Resolution:**
  1. Added `ExecutionContext.KEY_PRE_HEALING_TARGETS` and `ExecuteActionsStep.prepareStepForOnlineHealing(...)` to snapshot pre-healing targets and reset `failed`, `failureReason`, and `status = RUNNING` (plus sub-steps) before online healing, extracted `postStepVisualCaptureStep` to push after `AgentToolLoopStep` in both `HealingRequiredException` handlers, and cleared recovered `HealingRequiredException` from `ExecutionContext.KEY_LAST_EXECUTION_ERROR` in `endHookStep` upon step success.
  2. Updated `AgentToolLoopStep` (`dispatchActionExecutedEvent`, `buildCanonicalAction`, `buildResolvedAction`, `applyHealedMetadata`, `resolveHealedOriginalTarget`, `resolveTool`, `AgentToolLoopStep()`, and `finalizeStepExecution`) to mark healed actions, preserve `expectedTarget`/`originalTarget`, attach runtime-resolved `resolvedAction`, dispatch the 5-arg `ActionExecutedEvent`, support context `KEY_TOOL_REGISTRY` overrides when using the default registry, and clear `KEY_PRE_HEALING_TARGETS`.
  3. Added `ReportStepEntry.removeActionIf(Predicate<ReportActionEntry>)`, expanded `ReportStepEntry.isHealed()` to check actions and sub-steps, updated `PreliminaryReportListener` (`isStepSuccess`, `failureReason` clearing, `!a.isSuccess()` removal on healed action success, `recalculateMetrics()`, and `!this.report.isSuccess()` guard on `KEY_LAST_EXECUTION_ERROR` fallback in `populateContextMetadata()`), and added `"healed"` to `wasPassed` in `InteractiveConsoleEngine.reconcileTestOutcome`.
  4. Updated `InteractiveStateBuilder` to restrict the `report.getLlmCalls()` fallback to `reportStep == null` with exact `call.getStepIndex() == globalIndex`, and replaced single-pass `reportStep` matching with `findMatchingReportStep`.
  5. Updated `TestExecutionDto.isAiDriven()`, `RunStorageSyncService` (`!isHealed` guard on `isAi`, mutually exclusive `if (isHealed) ... else if (isAi)` counters, and `"HEALED"` variation mode priority), `TestRunEntity.get*AiCountSafe()` (`clampAiCount(...)` clamping against `categoryTotal - healedCount`), and `aura-manager/src/main/resources/static/js/report-manager.js` to prevent `Healed` + `AI-Driven` double-counting, preserve `'healed'` for composite sub-steps, fall back to healed sub-step screenshots when composite parent screenshots are empty, add `!isHealed` to `isUnexecutedOrSkipped`, and guard `hasEncounteredFailure` (with `?v=1.1.9` cache-buster in `index.html`).
- **Safety Net Added:**
  - `ExecuteActionsStepTest#testOnlineLlmHealingResetsPreMutatedFailedStatusAndReportsHealedOutcome` (including `KEY_LAST_EXECUTION_ERROR` cleanup and `SessionFinishedEvent` top-level `failureReason`/`failureStackTrace` null assertions)
  - `PreliminaryReportListenerTest#testSessionFinishedSuccessDoesNotRepopulateFailureFromStaleLastExecutionError`
  - `InteractiveConsoleEngineTest#testBuildStateJsonDoesNotDuplicateFallbackLlmCallsAcrossBlockIndices` and `"healed"` -> `"failed"` transition in `testReconcileTestOutcomeTransitionsRunningStatus`
  - `TestExecutionDtoTest#testOnlineHealedReplayExecutionIsNotDoubleCountedAsAiDriven`
  - `TestRunEntityTest#testAiCountClampedWhenHealedAndAiDoubleCountedInCategoryTotal`
  - `StaticResourceSyntaxTest#testHealedStepRenderingAndDownstreamPreservationInReportManagerJs` (including Node.js `renderStepsForExecution` behavioral checks)
  - Verified with `mvn test -pl neodymium-core -Dtest=ExecuteActionsStepTest,InteractiveConsoleEngineTest,PreliminaryReportListenerTest`, `mvn test -pl aura-manager -Dtest=TestRunEntityTest,TestExecutionDtoTest,StaticResourceSyntaxTest,RunStorageSyncServiceTest`, and `mvn install -DskipTests -Dmaven.javadoc.skip=true -pl neodymium-core,aura-manager`.
