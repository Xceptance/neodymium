# [DEF-20261123-1340] Premature Run Finished Modal Between Console Test Invocations

- **Status:** `Resolved`
- **Opened:** 2026-11-23 13:26
- **Closed:** 2026-11-23 13:50
- **Component:** `neodymium-core` (`NeodymiumAiRunner.java`, `InteractiveConsoleEngine.java`) & `aura-manager` (`LocalRunJsonStorageService.java`)
- **Scope:** `Framework`
- **Symptom:** When running a multi-dataset or multi-test suite from the console with `-Dneodymium.managerActive=true` (for example `WikipediaSearchTest` with 2 datasets), the Aura Manager dashboard opens the `"Run is finished. Would you like to open the report?"` modal (`#runFinishedModal`) immediately after the first test finishes, while the second test is still starting its browser.
- **Root Cause:**
  1. For external console runs (`isQueueRunning == false`), `AuraTestQueueController#getStatusStream` (`GET /api/status`, polled every 2 seconds by `dashboard-runner.js`) determines `running` exclusively via `LocalRunJsonStorageService#isRunCurrentlyActiveOnDisk(runId)`.
  2. `isRunCurrentlyActiveOnDisk(runId)` returned `true` only if at least one `console-execution-N.json` file on disk currently reported an in-flight step status (`"running"`, `"in_progress"`, `"executing"`, `"pending"`, or blank).
  3. Between Test 1's `SessionFinishedEvent` (`"status": "passed"` written to `console-execution-1.json`) and Test 2's first `StepStartedEvent` (`"status": "running"` written to `console-execution-2.json`), ~6–11 seconds elapse while Test 1 completes video recording, `BrowserExecutionCallback` quits Test 1's browser and launches Test 2's browser, and Test 2 parses its playbook.
  4. Because no run-level lifecycle signal distinguished "Test 1 completed while the JUnit run is still active" from "the entire JUnit test run completed", `isRunCurrentlyActiveOnDisk(runId)` returned `false` during the inter-test transition gap, causing `/api/status` to emit `"running": false` and `dashboard-runner.js` to invoke `showRunFinishedPrompt` right after Test 1.
- **Detection Gap ("What did we miss?"):** Existing unit and integration tests checked single-test `pushState` transitions (`"running"` -> `"failed"`) or post-run multi-file aggregation, without exercising the inter-test transition state where `console-execution-1.json` has already written a terminal status before `console-execution-2.json` is created on disk.
- **Resolution:**
  1. Added run-level lifecycle tracking in `InteractiveConsoleEngine` (`markRunActive`, `isJUnitRunActive`, `markRunFinished`, and `registerRunEngine`). While a JUnit run is active, `InteractiveConsoleEngine#pushState` registers the active engine and injects `"runActive": true` into outgoing state snapshots.
  2. Registered a root-scoped `JUnitRunLifecycleResource` (implementing `ExtensionContext.Store.CloseableResource` and `AutoCloseable`, backed by an idempotent JVM shutdown hook fallback) in `NeodymiumAiRunner#AiInvocationExtension#executeBeforeEach` so `InteractiveConsoleEngine.markRunFinished(runId)` pushes a final update carrying `"runActive": false` once the entire JUnit test plan finishes.
  3. Updated `LocalRunJsonStorageService#isRunCurrentlyActiveOnDisk(final String runId)` to keep the run active during inter-test transitions when a `"runActive": true` marker modified within 30 seconds is newer than any `"runActive": false` marker, immediately transitioning to inactive once `"runActive": false` arrives or after the 30-second lease expires on abnormal JVM termination.
- **Safety Net Added:**
  - `InteractiveConsoleEngineTest#testRunLifecycleMarksRunActiveBetweenTestsUntilMarkRunFinished` (`neodymium-core`): verifies `"runActive": true` persistence across multiple engines/datasets and `"runActive": false` emission upon `markRunFinished(runId)`.
  - `AuraReportStalenessRecoveryTest#testMultiTestConsoleRunStaysActiveBetweenTestsUntilRunFinished` (`aura-manager`): drives `AuraInteractiveService#pushState` through Test 1 completion (`"passed"`, `"runActive": true`), asserts `isRunCurrentlyActiveOnDisk` stays `true` and `TestRunEntity` remains `"IN_PROGRESS"` during the inter-test gap, completes Test 2, pushes `"runActive": false`, and verifies immediate transition to inactive and `"COMPLETED"`.
