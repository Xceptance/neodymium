# [DEF-20261113-1736] Stale Session Recency Dropdown and Fallback Session Mutation on Missing Confirm/Cancel

- **Status:** `Resolved`
- **Opened:** 2026-11-13 17:36
- **Closed:** 2026-11-13 17:36
- **Component:** `aura-manager`
- **Scope:** `Framework`
- **Symptom:** After sending messages or confirming/cancelling actions in a non-top chat session, the `#chatSessionSelect` dropdown kept stale session ordering until a manual page refresh; sending a blank prompt with a deleted `sessionId` rendered the fallback session's messages without updating `#chatSessionSelect`; and posting `/api/chat/confirm` or `/api/chat/cancel` for a deleted/unknown `sessionId` could fall back via `getSession(sessionId)` and persist assistant error/cancel messages into the default/most-recent session.
- **Root Cause:** [`AuraTestChatController`](file:///home/robert/Development/internal/neodymium/neodymium/aura-manager/src/main/java/com/xceptance/aura/test/controller/AuraTestChatController.java) only populated `chatSessions` + `oobSessionSelect = true` when a session was newly created or auto-renamed in `handleChat`, omitting OOB session-select updates on normal message appends, missing-session blank-prompt fallbacks, and confirm/cancel turns. Meanwhile `confirmPendingAction` and `cancelPendingAction` resolved sessions via `chatSessionService.getSession(sessionId)` instead of `findSession(...)`, causing missing IDs to resolve to and mutate the fallback session.
- **Detection Gap ("What did we miss?"):** `AuraTestChatControllerTest` mocked valid sessions for confirm/cancel and non-blank prompts for missing sessions, leaving blank-prompt missing-session fallback and confirm/cancel with missing/deleted `sessionId` unexercised.
- **Resolution:** Updated `handleChat`, `confirmPendingAction`, and `cancelPendingAction` in [`AuraTestChatController`](file:///home/robert/Development/internal/neodymium/neodymium/aura-manager/src/main/java/com/xceptance/aura/test/controller/AuraTestChatController.java) to refresh `chatSessions` and `oobSessionSelect = true` whenever recency order changes or a missing-session fallback occurs, and routed confirm/cancel lookups through `chatSessionService.findSession(...)` paired with `renderMissingSessionActionFragment(model)` so missing/blank session IDs render a transient read-only error without persisting to any fallback session.
- **Safety Net Added:** [`AuraTestChatControllerTest`](file:///home/robert/Development/internal/neodymium/neodymium/aura-manager/src/test/java/com/xceptance/aura/chat/controller/AuraTestChatControllerTest.java) methods `testConfirmAndCancelDoNotMutateFallbackSessionWhenExplicitSessionMissing`, `testHandleChatBlankPromptWithMissingExplicitSessionResyncsDropdown`, and OOB `oobSessionSelect` assertions in `testCustomNamedEmptySessionIsNotAutoRenamedOnFirstPrompt` and `testConfirmAndCancelEndpointsExecuteOrClearPendingConfirmation`.
