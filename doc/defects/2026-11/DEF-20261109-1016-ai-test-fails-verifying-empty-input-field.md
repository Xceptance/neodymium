# [DEF-20261109-1016] AI Test Fails When Trying to Verify That an Input Field Is Empty

- **Status:** `Resolved`
- **Opened:** 2026-11-09 10:16
- **Closed:** 2026-11-09 10:40
- **Component:** `neodymium-core`
- **Scope:** `Framework & AI/Prompt`
- **Symptom:** During AI test execution, asserting that an input field or element is empty (e.g. `assert_text(selector='#input', expectedText='')` or `ASSERT_TEXT` with `""`) failed with `IllegalArgumentException: Argument must not be null or empty string. Use $.shouldBe(empty) or $.shouldHave(exactText(""))` from Selenide's `PartialText` condition constructor. Furthermore, swapping to `exactText("")` was ineffective for `<input>` and `<textarea>` elements because WebDriver's `WebElement.getText()` returns an empty string even when the input element is populated with text.
- **Root Cause:**
  1. In `AssertAction.java` (`executeTextAssertion`), `Condition.partialText(matchText)` was invoked directly for non-regex assertions without intercepting empty strings (`matchText.isEmpty()`), violating Selenide's precondition that partial text arguments cannot be null or empty.
  2. While Selenide's `exactText("")` accepts empty strings, WebDriver's `WebElement.getText()` returns `""` on `<input>` and `<textarea>` elements, which caused `exactText("")` to falsely pass on populated inputs. Selenide's `Condition.empty` executes `Condition.and("empty", exactValue(""), exactText(""))`, correctly testing both `value` (for inputs and textareas) and text content (for divs, spans, and other containers).
  3. Neither `AssertAction.java` nor `BrowserToolProvider.java` provided first-class element state support for `"empty"` and `"not_empty"` in `ASSERT_ELEMENT_STATE` and `assert_element_state`.
  4. In `AssertAction.java`, `executeLegacyAssert()` utilized an explicit `if-else` chain comparing against literal string forms and did not delegate to `BrowserToolProvider.normalizeElementState()`, causing legacy assertions like `assert: empty` or `assert: [empty]` to fall into text content matching and fail.
  5. In `BrowserToolProvider.java`, `matchesCandidate(...)` used `candidate.toLowerCase().contains(unescaped.toLowerCase())`, which evaluates to `true` for any non-empty candidate when `unescaped` is `""`, causing populated elements to falsely match empty text queries during locator reanchoring and visual element verification.
  6. In `BrowserToolProvider.java` (`createAssertAttributeTool`), non-exact attribute assertions used `Pattern.compile(Pattern.quote(expectedValue))`. When `expectedValue` was empty, `Pattern.quote("")` matched every non-empty attribute value.
  7. In `BrowserToolProvider.java` (`createAssertTextTool`), negated assertions on delayed/asynchronous elements exited the polling loop prematurely (~1ms) before the element mounted in the DOM, falsely passing absent elements as satisfying negated text matches.
  8. In `BrowserToolProvider.java` (`createAssertTextTool`), empty text checks without a selector were allowed to proceed down the global page text assertion path, creating ambiguity rather than failing fast.
  9. In `AssertAction.java` (`executeLegacyAssert`), the switch statement over `normalizeElementState(expected)` omitted branches for `"exists"`, `"absent"`, `"unfocused"`, and `"unselected"`, while retaining dead code `case "present":` (since `"present"` is normalized to `"exists"`).
  10. In both `AssertAction.java` and `BrowserToolProvider.java`, `editable` and `readonly` were omitted from state negation mappings, preventing proper inversion when negated.
  11. In `BrowserToolProvider.java` (`matchesElementText`), `<input>` and `<textarea>` elements evaluated `el.getText()` first; because WebDriver returns `""` for `getText()` on `<input>`, empty regexes such as `^$` falsely passed on populated inputs.
  12. In `BrowserToolProvider.java` (`createAssertTextTool`), catching a stale element exception under negation erroneously set `matched = true`, which would cause false positive "forbidden text found" assertion errors when polling timed out.
  13. In `AssertAction.java` (`executeLegacyAssert`), `case "hidden":` was omitted from the switch statement, causing legacy assertions for `hidden` and `invisible` to execute content text searches for `"hidden"` instead of evaluating `Condition.hidden`.
  14. In `BrowserToolProvider.java` (`createAssertTextTool`), empty text checks using `selector: "body"` or `selector: "html"` bypassed the fast-fail guard due to an inverted `!expectedText.isEmpty()` check, resulting in a 4,000ms polling timeout on the document body rather than an actionable error.
  15. In `AssertAction.java` (`ASSERT_UNFOCUSED`, `executeLegacyAssert`, `executeCompoundStateAssertion`) and `BrowserToolProvider.java`, unfocused checks only checked `shouldNotBe(Condition.focused)` or executed a single synchronous JS snippet without Selenide polling; if the element was momentarily focused during async transitions, it failed immediately without polling.
  16. In `AssertAction.java` (`executeLegacyAssert`), an upfront `isAbsenceCheck` header intercepted `hidden` and `absent` strings, making subsequent `case "hidden":` and `case "absent":` in the switch statement unreachable dead code.
  17. In `BrowserToolProvider.java` (`createAssertTextTool`), root selector detection for blank text assertions only checked literal `"body"` and `"html"`, allowing XPath (`//body`, `/html/body`) and nested CSS (`html > body`, `html body`) to bypass the fast-fail guard and time out.
  18. In `AssertAction.java` (`UNFOCUSED`), the custom `WebElementCondition` caught `Exception` generically without rethrowing `StaleElementReferenceException`, which on dynamically re-rendering elements caused stale reference failures during document focus checks to fall through and report the element as unfocused, creating false positive passes.
  19. In `BrowserToolProvider.java` (`isRootElementSelector`), selector prefix markers (`css=`, `xpath=`), whitespace variations, and root forms (`:root`, `/html/body[1]`, `//body[1]`) were not stripped or normalized, allowing prefixed or indexed root expressions to bypass fast rejection.
  20. `AssertAction` and `BrowserToolProvider` lacked a symmetric `AssertAction.FOCUSED` condition for `focused` assertions, and `browser_assert_element_state` routed `focused` to Selenide's default `Condition.focused` rather than checking document active element / `:focus`.
- **Detection Gap ("What did we miss?"):** Existing assertion test cases in `AssertActionTest` and `BrowserToolsTest` only verified non-empty string literals (e.g. `"Welcome"`, `"CAD $"`, `"50 €"`). No tests exercised `assert_text` or `ASSERT_TEXT` with an empty string `""` on input or textarea elements, nor did tests verify negated text assertions on delayed DOM nodes, empty attribute matching, empty regexes on input elements, legacy `hidden`/`invisible` assertions, root element (`body`/`html`, `//body`, `html > body`, `css=body`, `:root`, `/html/body[1]`) empty text rejection, polling for async focus/unfocused state, stale element handling in focus checks, or legacy state normalization edge cases (`exists`, `absent`, `unfocused`, `unselected`, `editable <-> readonly`).
- **Resolution:**
  1. In `AssertAction.java` (`executeTextAssertion`), intercepted `matchText.isEmpty()` to delegate directly to `element.shouldBe(Condition.empty)` (or `element.shouldNotBe(Condition.empty)` when negated).
  2. In `AssertAction.java` (`executeCompoundStateAssertion`), added first-class `"empty"` and `"not_empty"` states mapping to `element.shouldBe(Condition.empty)` / `element.shouldNotBe(Condition.empty)` with symmetric negation.
  3. In `AssertAction.java` (`executeLegacyAssert`), refactored the legacy dispatch into a `switch (BrowserToolProvider.normalizeElementState(expected))` supporting `"empty"`, `"not_empty"`, `"hidden"`, `"exists"`, `"absent"`, `"unfocused"`, `"unselected"`, and bracketed/alias variants, eliminating dead code.
  4. In `BrowserToolProvider.java`, added `"empty"` and `"not_empty"` to the `assert_element_state` tool parameter schemas, state enum lists, negation mapping, and evaluation switch.
  5. In `BrowserToolProvider.java` (`normalizeElementState`), normalized `"blank"` and `"empty"` to `"empty"`, and `"not_empty"`, `"non_empty"`, `"not-empty"`, `"non-empty"`, `"not empty"`, `"non empty"`, `"not blank"`, `"non blank"` to `"not_empty"`.
  6. In `BrowserToolProvider.java` (`matchesCandidate`), returned `candidate.isBlank()` when `expectedText.isEmpty()`, preventing substring `.contains("")` false positive matches on populated candidates.
  7. In `BrowserToolProvider.java` (`matchesElementText`), delegated to `se.is(Condition.empty)` when `expectedText == null || expectedText.isEmpty()`. For non-empty strings, inspected `getValue()` directly on `<input>` and `<textarea>` elements to prevent `el.getText() == ""` false positives with empty regexes (`^$`).
  8. In `BrowserToolProvider.java` (`matchesElementOrAssociatedLabel` and `isTextPresentOnPage`), prevented falling back to element labels or entire page body text when `expectedText` is empty.
  9. In `BrowserToolProvider.java` (`createAssertTextTool` and `isRootElementSelector`), required a specific target selector when asserting empty text, unconditionally fast-failing `null`, blank, root tags (`body`, `html`), XPath (`//body`, `/html/body`, `/html/body[1]`, `//body[1]`), descendant selectors (`html > body`, `html body`, `html>body`), and `:root` (including `css=` and `xpath=` prefixes) with an actionable error node.
  10. In `BrowserToolProvider.java` (`createAssertTextTool`), tracked `elementExists` during polling for negated assertions, ensuring delayed elements have up to `Configuration.timeout` to mount before concluding non-existence or match state.
  11. In `BrowserToolProvider.java` (`createAssertTextTool`), removed `if (negated) { matched = true; }` inside the stale element exception catch block so retry polling does not record a false match.
  12. In both `AssertAction.java` and `BrowserToolProvider.java`, wired bidirectional negation between `"editable"` and `"readonly"`.
  13. In `BrowserToolProvider.java` (`createAssertAttributeTool`), enforced exact matching when `exact || expectedValue.isEmpty()` to eliminate empty substring regex overmatching.
  14. Introduced `AssertAction.UNFOCUSED` and `AssertAction.FOCUSED` as `WebElementCondition`s checking both `driver.switchTo().activeElement()` and `document.activeElement / :focus`, rethrowing `StaleElementReferenceException` so Selenide's proxy retry loop can re-locate the element, enabling full Selenide polling until timeout across `AssertAction` and `BrowserToolProvider`.
  15. In `neodymium-test-server`, enhanced `testAssertHappyPath.html` with `#empty-input`, `#empty-div`, `#whitespace-div`, `#empty-textarea`, and `#populated-textarea`.
- **Safety Net Added:**
  - `AssertActionTest#testAssertActionEmptyTextAssertions` asserting `ASSERT_TEXT` with `""` passes on empty inputs, divs, textareas, and whitespace containers, fails on populated inputs/textareas, and handles negation properly.
  - `AssertActionTest#testAssertActionEmptyElementState` asserting `ASSERT_ELEMENT_STATE` and legacy `ASSERT` with `"empty"`, `"[empty]"`, `"not_empty"`, and aliases across empty and populated inputs, textareas, and containers.
  - `AssertActionPluginTest#testLegacyAssertExistsAndPresent`, `testCompoundStateNegationEditableInvertsToReadonly`, `testLegacyAssertUnfocused`, `testLegacyAssertUnfocusedFailsWhenFocused`, `testLegacyAssertUnfocusedWithAsyncFocusPolling`, `testLegacyAssertFocusedWithAsyncFocusPolling`, `testFocusedAndUnfocusedRethrowStaleElementReferenceException`, and `testLegacyAssertHiddenAndInvisible` verifying legacy state dispatch, async focus polling, staleness rethrowing, and bidirectional negation.
  - `BrowserToolsTest#testAssertionToolsParameterSchema` verifying `"empty"` and `"not_empty"` are declared in the `assert_element_state` parameter schema enum.
  - `BrowserToolsTest#testNormalizeElementStateEmpty` and `BrowserToolProviderStabilityTest#testNormalizeElementStateUtility` verifying normalization of `"empty"`, `"blank"`, `"[empty]"`, `"EMPTY"`, `"not_empty"`, `"non_empty"`, `"not-empty"`, `"non-empty"`, `"not empty"`, `"non empty"`, `"not blank"`, `"non blank"`.
  - `BrowserToolsTest#testMatchesCandidateWithEmptyExpectedText` and `BrowserToolProviderStabilityTest#testMatchesCandidateWithEmptyExpectedText` verifying candidate matching returns true only for blank candidates and false for populated candidates when expected text is empty.
  - `BrowserToolProviderStabilityTest#testMatchesElementTextOnPopulatedInputWithEmptyRegex` verifying that empty regex (`^$`) on populated inputs returns `false`.
  - `BrowserToolProviderStabilityTest#testAssertElementStateReadonlySuccessAndEditableFailure` verifying `editable <-> readonly` negation inversion.
  - `BrowserToolProviderStabilityTest#testAssertElementStateEmptyAndNotEmptyToolExecution` verifying schema enums, tool execution for empty/not_empty state assertions, negated states, `assert_text` empty strings, `matchesElementText`, and `browser_assert_attribute` with empty expectedValue.
  - `BrowserToolProviderStabilityTest#testAssertTextEmptyWithoutSelectorReturnsError` and `testAssertTextEmptyExpectedTextWithoutSelectorRejection` verifying fast-fail error when asserting empty text without a selector or against root container selectors (`body`, `html`, `//body`, `html > body`, `css=body`, `:root`, `xpath=/html/body[1]`).
  - `BrowserToolProviderStabilityTest#testNegatedAssertTextWaitsForDelayedElement` verifying polling continues for delayed elements under negated text assertions.
