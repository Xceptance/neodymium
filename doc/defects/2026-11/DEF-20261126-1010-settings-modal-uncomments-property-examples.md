# [DEF-20261126-1010] Aura Manager Settings Modal Uncomments Property Examples and Corrupts Config Files on Save

- **Status:** `Resolved`
- **Opened:** 2026-11-26 10:10
- **Closed:** 2026-11-26 14:14
- **Component:** `neodymium-core` (`AuraSettingsService`), `aura-manager` (`AuraTestSettingsController`, `settings-modal.html`)
- **Scope:** `Framework` & `Config/Environment`
- **Issue:** GitLab `#176`
- **Symptom:**
  Editing a single value and clicking **Save Settings** in the Aura Manager Settings modal uncommented and activated almost every commented-out example property across all discovered `.properties` files in `config/` (including hazardous examples such as `neodymium.url.excludeList`, `neodymium.url.includeList`, and placeholder `/path/to/...` WebDriver binary paths), overwrote active properties when a commented example of the same key appeared earlier in the file (e.g., `#neodymium.url = http://localhost:8080/en-US/`), converted prose comments containing `:` or `=` (`# NOTE:`, `# Warning:`, `# Range:`, `# Default:`, `# ATTENTION:`, `#   1.0 = ...`) into active bogus properties, reformatted untouched files on disk, and rewrote/created `dev-neodymium.properties` from scratch while discarding all existing comments.
- **Root Cause:**
  1. `AuraSettingsService.parsePropertyFile` matched commented lines against `COMMENTED_KEY_PATTERN` (`^\s*[#!]\s*([a-zA-Z0-9_.-]+)\s*[:=]\s*(.*)$`), emitting `PropertyEntryDto(..., active = false, ...)` entries with example values and inserting prose tokens into `allKnownKeys`, while failing to reset `currentCommentLines` on blank lines, bare `#` separators, or commented-out property examples (allowing comments from commented blocks to bleed into subsequent active properties in both `parsePropertyFile` and `parseBrowserPropertyFile`).
  2. `settings-modal.html` rendered every `PropertyEntryDto` without checking `entry.active` inside a single `<form>` spanning every discovered `.properties` file (and compared boolean `<option>` selection case-sensitively, flipping mixed-case active `False` to `true` on save), causing **Save Settings** to POST commented entries across all files; `AuraTestSettingsController.getSettingsJson` likewise lacked an `entry.isActive()` guard, and `saveSettings` unconditionally called `saveDevNeoProperties` even when `devNeoKey` was omitted from `formData`.
  3. `AuraSettingsService.savePropertyFile` matched `COMMENTED_KEY_PATTERN` and uncommented every matching line with a non-empty value, blindly appended non-active keys at EOF, reformatted unchanged active lines as `key = value`, and unconditionally called `Files.write(...)` on untouched files.
  4. `AuraSettingsService.saveDevNeoProperties` unconditionally created `dev-neodymium.properties` (even when absent and empty) and overwrote the file from a hardcoded header template instead of updating active lines in place and preserving existing comments.
- **Detection Gap ("What did we miss?"):**
  `AuraSettingsServiceTest#testSavePropertyFilePreservingComments` explicitly encoded and asserted the buggy uncommenting behavior (`#neodymium.ai.generate = false` becoming `neodymium.ai.generate = true`), no test exercised `parsePropertyFile` on realistic property files containing commented examples, prose comments with `:`/`=`, duplicate commented+active keys, or comment-block boundaries, no test verified that untouched files avoid disk writes, `saveDevNeoProperties` had zero unit test coverage, and `settings-modal.html` had no template rendering test checking active-only rows and case-insensitive boolean selection.
- **Resolution:**
  1. Removed `COMMENTED_KEY_PATTERN` parsing and uncommenting in `AuraSettingsService`; parsed only active properties into `PropertyEntryDto` and `allKnownKeys`; introduced `COMMENTED_PROPERTY_EXAMPLE_PATTERN` strictly to reset `currentCommentLines` alongside blank-line and bare `#` resets in `parsePropertyFile` and `parseBrowserPropertyFile`.
  2. Updated `AuraSettingsService.savePropertyFile` to preserve all blank/comment lines and unchanged active lines verbatim, skip disk writes and `AiConfiguration.resetInstance()` when unmodified, and restrict appending new keys to a private overload invoked explicitly by `addBrowserProperty`.
  3. Updated `AuraSettingsService.saveDevNeoProperties` to skip creating an absent file when `devNeoEntries` is empty, preserve all existing comments and unchanged active lines verbatim, update/add/remove only active entries, and skip disk writes when unchanged.
  4. Added `entry.active` defense-in-depth guards and `#strings.equalsIgnoreCase` boolean `<option>` selection in `settings-modal.html` (plus a read-only empty-file message), added `entry.isActive()` filtering in `AuraTestSettingsController.getSettingsJson`, and guarded `saveDevNeoProperties` in `AuraTestSettingsController.saveSettings` on `formData.containsKey("devNeoKey")`.
- **Safety Net Added:**
  - `AuraSettingsServiceTest`: updated `testSavePropertyFilePreservingComments` and added `testParsePropertyFileIgnoresCommentedExamplesAndProseWithColons`, `testParseBrowserPropertyFileDoesNotBleedCommentedExampleIntoDescription`, `testSavePropertyFileNeverUncommentsOrOverwritesWithEarlierCommentedSameKey`, `testSavePropertyFilePreservesUnchangedLinesAndSkipsDiskWriteForUntouchedFile`, `testSavePropertyFileDoesNotCreateMissingFileWhenUpdating`, `testAddBrowserPropertyAppendsWithoutUncommentingCommentedExample`, `testSaveDevNeoPropertiesDoesNotCreateFileWhenAbsentAndEmpty`, `testSaveDevNeoPropertiesCreatesFileWhenAbsentAndNonEmpty`, `testSaveDevNeoPropertiesPreservesCommentsAndSkipsWriteWhenUnchanged`, `testSaveDevNeoPropertiesUpdatesAddsAndRemovesActiveKeysWhileKeepingComments`, and `testMultiFileLoadAndSinglePropertySaveLeavesOtherFilesAndCommentsUntouched`.
  - `AuraTestSettingsControllerTest`: added `testGetSettingsJsonExcludesInactiveEntries`, `testSaveSettingsDoesNotInvokeSaveDevNeoWhenFormOmitsDevNeoKey`, `testSaveSettingsInvokesSaveDevNeoWithEmptyListWhenUserClearsAllOverrides`, `testSaveSettingsWithRealServicePreservesCommentsAndUntouchedFiles`, and `testSettingsModalTemplateRendersOnlyActiveEntriesAndCaseInsensitiveBooleans`.
