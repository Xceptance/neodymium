# [DEF-20261016-1426] Interactive Console Structural Mutation Race Condition and Missing Visual Sync Feedback

- **Status:** `Resolved`
- **Opened:** 2026-10-16 14:26
- **Closed:** 2026-10-16 14:32
- **Component:** `neodymium-core`
- **Scope:** `Framework`
- **Symptom:** Adding or reordering steps while a prior structural mutation request is in-flight causes subsequent user actions (e.g. dragged steps, temporary new steps, inline edits) to be silently dropped or reverted when the asynchronous Server-Sent Events (SSE) state snapshot arrives. Furthermore, during this sync period, the interface provides no visual indication (spinner or banner), creating the impression of a frozen or unresponsive test execution UI.
- **Root Cause:** In `interactive_console.js`, `isStructuralActionInFlight` guarded only execution controls (`#btnRun`) but did not disable drag-and-drop containers (`.steps-block-content`), step number badge inputs (`.step-num-badge input`), or add-step buttons (`.add-step-card-btn`). Optimistic local mutations (`currentState.blocks.splice`) made while an action was in transit were completely replaced when `applyState(data)` processed the server's prior-state SSE broadcast. Additionally, no visual sync indicator was rendered, and no watchdog timeout existed to recover from dropped SSE packets.
- **Detection Gap ("What did we miss?"):** Existing interactive view unit and integration tests executed discrete actions sequentially with complete pauses, never asserting that overlapping UI interactions during the transit window are safely guarded and visually indicated.
- **Resolution:**
  1. Added `#timelineSyncIndicator` with rotating `progress_activity` icon and status text ("Structuring changes...") at the top of the steps timeline in `interactive_console.html` and styled in `interactive_console.css`.
  2. Extended `setButtonsEnabled` in `interactive_console.js` to show/hide the sync indicator, apply `.drag-disabled` to `.steps-block-content`, disable `.add-step-card-btn` without layout-collapsing display flips, disable and blur `.step-num-badge input` (setting `disabled` and `readonly` attributes alongside `.sync-disabled` class), and disable inline card action buttons (`.step-edit-btn`, `.step-add-after-btn`, `.step-rewind-btn`, `.step-delete-btn`) during `isStructuralActionInFlight`.
  3. Enforced `disabled="true"` and class `.disabled` in `renderStepCard()` for inline action buttons as well as `disabled readonly` and `.sync-disabled` on `.step-num-badge` when `isStructuralActionInFlight` is true.
  4. Added explicit CSS rules in `interactive_console.css` for `.step-edit-btn:disabled`, `.step-add-after-btn:disabled`, `.step-rewind-btn:disabled`, `.step-num-badge input:disabled`, `.step-num-badge.sync-disabled`, and `.steps-block-content.drag-disabled` child elements (`pointer-events: none !important; opacity: 0.25-0.45 !important;`), neutralizing active selection borders and text cursor, and scoped `:hover` rules to `:not(:disabled):not(.disabled):hover` to prevent active blue hover highlights during sync.
  5. Added programmatic guards against `isStructuralActionInFlight` in `openAddStepOverlay()`, `addStepAfter()`, `enableEdit()`, `triggerRewind()`, `moveStep()`, `handleDragStart()`, `reorderStep()`, `handleStepInputInput()`, `restoreFocus()`, and keydown shortcuts.
  6. Implemented a 5-second `startStructuralSyncWatchdog()` safety net to auto-clear the sync lock and re-enable controls if an SSE broadcast is delayed or dropped.
- **Safety Net Added:** Added automated test in `InteractiveConsoleServerTest#testStructuralMutationLockAndVisualSyncIndicator` in `neodymium-core/src/test/java/com/xceptance/neodymium/ai/console/InteractiveConsoleServerTest.java` verifying that the structural sync indicator, drag handles, inline action buttons (`.step-add-after-btn`, `.step-edit-btn`, `.step-rewind-btn`), step number badge inputs (`.step-num-badge input`), input debounce handlers, and hover CSS selectors transition into disabled states during in-flight structural actions and recover cleanly.
