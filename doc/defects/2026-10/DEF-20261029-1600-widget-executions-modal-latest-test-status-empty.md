# [DEF-20261029-1600] Empty Test Executions Table in Contributing Executions Modal for Latest Test Status Widgets

- **Status:** `Resolved`
- **Opened:** 2026-10-29 16:00
- **Closed:** 2026-10-29 16:07
- **Component:** `aura-manager`
- **Scope:** `Framework`
- **Symptom:** Opening the Contributing Executions modal on non-trend dashboard widgets configured with `PointScope: LATEST_TEST_STATUS` (e.g. Costs Pie Chart, Status Pie Chart, Ratio Bars) listed the contributing runs (e.g., `#run_stg_emea_20261021_092780 ... 103 tests`), but the expanded body of each run showed no test execution rows, displaying instead the fallback message: *"Execution details cataloged at run-level (103 total tests). Open run report for trace breakdown."*
- **Root Cause:** In `WidgetAggregationService.resolveContributingExecutions`, execution filtering for `isLatestVariationScope` checked `latestVarKeys.contains(execKey) || (rowId != null && latestVarKeys.contains(rowId))`. However, `latestVarKeys` contains canonical `logicalKey` strings generated by `AuraReportDataService.buildLogicalKey` formatted with pipe delimiters and uniqueness identity dimensions (`class|method|dataset|br:...|loc:...|env:...|tag:...`). The naive `execKey` used `#` delimiters and lacked identity dimensions, while `rowId` is an execution instance UUID (`exec-1234`). Consequently, `matchesKey` evaluated to `false` for 100% of executions, discarding all test rows. Furthermore, for the `COSTS` metric, tests with 0 LLM cost were unconditionally filtered out even in runs with 0 total cost. Finally, when `runExecutions` became empty, the service unconditionally fell back to run summary counts, causing the accordion to claim "103 tests" despite displaying 0 execution rows.
- **Detection Gap ("What did we miss?"):** Existing test `testResolveContributingExecutions_WithDataService` only tested `WidgetPointScope.LAST_RUN` without `latestVariations`, completely omitting `WidgetPointScope.LATEST_TEST_STATUS` and variation logical key matching.
- **Resolution:**
  1. Enriched `BatchLatestVariationDto` with an `executionId` field populated by `AuraReportDataService.getBatchLatestTestExecutionsSummary`.
  2. Added a convenience overload `buildLogicalKey(final TestRunEntity run, final TestExecutionDto exec)` in `AuraReportDataService`.
  3. Upgraded `WidgetAggregationService.resolveContributingExecutions` to scope variations per contributing run, matching executions by exact `executionId`, canonical `buildLogicalKey(run, exec)`, and fallback keys for synthetic tests.
  4. Refined `COSTS` metric filtering to retain contributing executions in zero-cost runs and sort executions by cost and token usage descending.
  5. Guarded run entity summary count fallbacks to only trigger when execution traces could not be loaded from storage.
- **Safety Net Added:** Added automated regression tests in `WidgetAggregationServiceTest`: `testResolveContributingExecutions_LatestTestStatus_PopulatesExecutionsViaLogicalKey` and `testResolveContributingExecutions_CostsMetric_ZeroCostRunShowsExecutions`.
