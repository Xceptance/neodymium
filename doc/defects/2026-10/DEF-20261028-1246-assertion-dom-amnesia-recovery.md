# [DEF-20261028-1246] Prevent false-negative assertion aborts caused by multi-turn DOM pruning amnesia

- **Status:** `Resolved`
- **Opened:** 2026-10-28 12:46
- **Closed:** 2026-10-28 13:51
- **Component:** `neodymium-core`
- **Scope:** `Framework & AI/Prompt`
- **Symptom:** During compound test instructions (e.g., verifying multiple visual elements/text in a shopping cart), after Turn 1, prior DOM snapshots are pruned from conversation history (`pruneExpiredDomFromConversation`) per [DEF-20260930-07](doc/defects/2026-09/DEF-20260930-07-unpruned-dom-in-multi-turn-verification.md). When instructions do not have discrete sub-step milestones, `hasRemainingMilestones` evaluates to `false`, causing `requireDomForNextTurn` to remain `false`. Lightweight models (such as `gemini-3.5-flash-lite`) suffer from DOM amnesia, omit calling `query_dom`, and hallucinate generic eCommerce selectors (e.g. `app-cart-item select, app-cart-item app-quantity-selector`). When Selenide fails to find the element, it throws `ElementNotFound` (an `AssertionError`), which immediately triggers Stop Criterion 2 (`AgentToolLoopStep.java:L1244-1250`), aborting the test without allowing context recovery.
- **Root Cause:**
  1. In `BrowserToolProvider.java`, `assert_text` and `assert_attribute` already caught `ElementNotFound` and returned a recoverable `ToolResult.error` when the target element was missing from the DOM. However, `assert_element_state` did not catch `ElementNotFound` or `NoSuchElementException`, allowing Selenide's runtime exception to bubble up unhandled.
  2. In `AgentToolLoopStep.java`, the tool execution loop caught `AssertionError` and unconditionally treated any assertion tool (`assert_*`, `browser_assert_*`) as a fatal defect triggering Stop Criterion 2. While action tools (`click`, `fill`) treated element lookup failures as recoverable errors (escalating context level and attaching fresh DOM on the next turn), assertion tools immediately aborted. When an assertion failed with `ElementNotFound` specifically on a turn where the DOM snapshot was pruned and omitted (`!domAttachedToCurrentTurn`), the framework misinterpreted agent context starvation / blindness as a fatal SUT assertion defect.
- **Detection Gap ("What did we miss?"):** Multi-turn unit tests for assertion tools in `AgentToolLoopStepTest` only covered single-turn assertions where the initial DOM was present, or mocked successful tool execution without simulating `ElementNotFound` on pruned/omitted DOM turns. Furthermore, `BrowserToolProviderStabilityTest` tested `assert_element_state` on existing DOM nodes but lacked a test verifying behavior when elements were completely absent from the DOM.
- **Resolution:**
  1. In `BrowserToolProvider.java` (`createAssertElementStateTool`), added handling for `ElementNotFound` and `NoSuchElementException`: if no matching element exists in the DOM, it returns `ToolResult.error` (matching `assert_text` and `assert_attribute`). If elements exist in the DOM (e.g. asserting `visible` on a hidden element), `ElementNotFound` is rethrown as an `AssertionError` to preserve genuine SUT verification failures.
  2. In `AgentToolLoopStep.java`, tracked `domAttachedToCurrentTurn`. If an assertion tool fails due to an element lookup failure (`isElementNotFoundFailure(...)`) on a turn where the DOM was omitted (`!domAttachedToCurrentTurn`), the failure is converted to a recoverable `ToolResult.error` explaining that the prior DOM snapshot was omitted and scheduling a fresh DOM snapshot with escalated context depth (`requireDomForNextTurn = true`).
  3. Preserved immediate Stop Criterion 2 hard-abort when `domAttachedToCurrentTurn == true` or when the failure represents an actual content/value/state mismatch on an existing element.
  4. Linked to GitLab Issue #103 (`[neo] Prevent false-negative assertion aborts caused by multi-turn DOM pruning amnesia`).
- **Safety Net Added:**
  - `BrowserToolProviderStabilityTest.testAssertElementStateReturnsErrorWhenElementNotFoundInDom`: Verifies that `assert_element_state` returns a `ToolResult.error` when the selector matches 0 elements in the DOM.
  - `BrowserToolProviderStabilityTest.testAssertElementStateThrowsAssertionErrorWhenStateMismatchesOnExistingElement`: Verifies that `assert_element_state` rethrows `AssertionError` when the target element exists in the DOM but fails state verification (e.g. `enabled` on a disabled element).
  - `AgentToolLoopStepTest.testAssertionElementNotFoundOnOmittedDomTurnTriggersJitDomRecovery`: Validates that when an assertion fails with `ElementNotFound` on an omitted-DOM turn, the loop recovers, attaches fresh DOM on Turn 3, and successfully completes the step.
  - `AgentToolLoopStepTest.testAssertionElementNotFoundWhenDomPresentTriggersStopCriterion2`: Validates that when DOM is present on Turn 1 and an element is missing, Stop Criterion 2 triggers immediately.
